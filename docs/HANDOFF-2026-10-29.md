## 2. 项目目标与用户已经确定的取舍

把原 CP 和 FT 工具整合为一个本地数据工作台，统一入口、输入输出、任务日志、结果打开和历史记录，复用原工具的计算规则。当前阶段只做本地分析。

- 功能、性能、稳定性是三个最高优先级；装饰效果影响速度时应简化。
- 保持现有框架，用户已经放弃本轮 Rust/Tauri 重写方案。
- CP、FT 是侧边栏独立工作台，分别维护工厂和功能选择，避免所有操作挤在一页。
- 工厂未来会增长到每类约 10～20 家；现有选择器采用可筛选卡片和受控布局。
- 正常入口只使用真实数据，不展示“演示数据”“真实分析结果”切换按钮。
- Excel/CSV/报告通过结果文件夹查看，APP 不自动读取、渲染完整输出表。
- 待分析输入列表每次启动为空；用户可移除导入项，移除不删除原始文件。完整历史在历史页维护。
- 输入路径可见，统一选择文件或文件夹并自动识别；记住上次输入位置。压缩格式必须以当前操作允许的格式为准。
- 输出默认使用 Windows 当前用户桌面，含 OneDrive/重定向桌面识别；修改后记作默认路径。输出按既有规则另建批次/时间目录，不能覆盖原始数据。
- 当前路径层只接受本机绝对路径并拒绝 UNC 网络共享；不要把文件/文件夹支持理解为已支持任意网络盘路径。
- 当前只有一个计算任务运行，其余排队；开始清洗自动进入任务进度页，显示滚动日志和取消入口。
- 本地图表继续保留，按需打开。FT 图表与清洗/PAT/SBL-SYL 分区。
- `JETECH` 的中文名称固定为“佳泰”，不能写成“积塔”。内部代码仍用 `JETECH`。
- 历史原件和输出数据不为名称修正而批量改写；界面可按工厂代码映射正确名称。

## 4. 不能破坏的数据规则

### 身份、规格和解析

产品、完整批次、Lot、Wafer、测试程序、条件、单位、规格和 Bin 必须保留真实业务含义。通过内容特征、动态表头与规格识别格式，不能只按扩展名或固定列名猜测。

格式未知、身份冲突、规格/条件不兼容和真实重复需要明确拒绝，不能用“清洗成功”掩盖丢失数据。华虹 TD 与 DCP/TXT 是不同输入族，不可混合。目录中同时含不同 FT 类型时，必须选择与当前操作匹配的数据；上海捷敏 `data8` 不能整个当作 DC 目录提交。

上海捷敏保留明确业务批次；`NCEG` 是源追溯编号，不能直接当制造批次。缺失批次时按固定 FT 引擎已验证的规则处理，参数按含义、条件、单位和出现次数区分。

### 华虹 DCP/TXT 原始 PAT

这是最新一次重要业务修复，新项目必须保留：

- `NCEVTG120EV60DA_FA69-9491@203`：产品为 `NCEVTG120EV60DA`，完整批次为 `FA69-9491`，站号为 `203`。
- 每个兼容产品汇总生成一个 `<产品>_PAT_YYYYMMDD_HHMMSS.xlsx`；不再按站号或程序拆成两份报告。多个产品各自输出一份。
- 合并前检查参数、单位、规格和测试条件。只对兼容原始值合并后重算，不平均旧报告统计值，也不自动选择“最近一次”。
- 使用固定 FT 原始 PAT 引擎：线性分位数，`Sigma=(Q3-Q1)/1.35`，中位数 ±6Sigma，样本标准差 `ddof=1`。这是该入口口径，不能替换成旧 CP 的 5Sigma/1.349。
- 保留失败 Bin、有限超规格值；不先做 IQR 离群点删除。No.U、坐标和 Bin 不作为测量参数。
- SI 原始值按源规格单位显示，例如 A 转为 nA，避免小电流被舍入成零。
- 输出遵循 FT 的 PAT 工作表、17 列及“变量”行格式。“更新前”为源规格，“更新后”“是否更新”留空。
- 用户输出目录只放 PAT Excel；`PAT_source_manifest.json`、汇总 JSON 和完整归档保留在内部任务目录。
- 当前此新增入口针对 DCP/TXT，不代表 TD Excel 已支持同一套原始 PAT。
- 相同采集范围的 Lot/Wafer 真重复仍拒绝；不要误删不同批次、站号或已被明确区分的采集数据。

入口实现重点：`engine_support/desktop_client/nce_desktop/local_cp_pat.py`、`local_cp_input.py`、`local_native_worker.py`。独立对账工具：`packaging/validate_huahong_pat.py`。详情见 [华虹 PAT 业务说明](HUAHONG-PAT-2026-10-28.md)。

## 5. 技术结构与查找入口

现有技术栈为 PySide6/Qt WebEngine 桌面外壳 + React/TypeScript/Vite 界面 + Python 本地核心，PyInstaller 生成目录式 Windows 程序，NSIS 生成用户安装包。

用户操作经 QWebChannel 到 Python Core；任务进入串行队列，再由独立计算进程运行固定 CP/FT 引擎，产生内部回执并将原报告发布到用户输出目录，最后保存本地历史。

| 模块 | 作用 / 主要文件 |
| --- | --- |
| `apps/web/src/App.tsx` | 工作台、导航、历史/结果页和状态切换 |

| `apps/desktop/` | `main.py`、`shell.py`、`bridge.py`、`security.py`、`rendering.py` |
| `python_core/core.py` | 本地 SQLite、任务、设置、业务操作与应用版本 |

## 6. 环境、用户数据和性能约束

- 构建环境：项目内 `.runtime/python313` 与 `.venv-cpython`。依赖按 `environments/core.lock`、`studio.lock`、`cp-viewer.lock` 固定；不使用系统 Anaconda 拼装运行时。
- 计算环境：`engines/runtime/python.exe`。`engine-pins.json` 固定 CP、native FT、shared FT 包与原 runtime 输入哈希；`engines/manifest.json` 固定实际文件和工具目录。
- 两份 FT 包的 native/shared profile 是有意区分的；替换引擎时需要核对操作来源、合同和全部哈希，不能仅改文件名。
- 开发态从项目根目录找 `engines`；冻结态从 EXE 同级找 `engines`。隔离 PYTHON/QT/CONDA/TMS/PYMS 环境变量和 DLL 搜索路径。
- 本地用户工作区：`%LOCALAPPDATA%\NCE\DesktopDataStudio-M0`，当前开发机为 `C:\Users\wgs03\AppData\Local\NCE\DesktopDataStudio-M0`；其中含 `history.sqlite`、日志和内部 results 等。保留 M0 名称是为了延续历史，不要直接改目录名。
- 个人历史、实际输入、输出、日志、运行环境和发布二进制不提交 Git。用户实际选择的输出目录独立于程序安装目录。
- 单任务计算，不因增加线程就宣称更快；界面不能承担真实数据解析。日志每次最多增量读取 64KiB，前端保留最多 1000 行/60000 字符，磁盘完整日志保留。
- Windows 默认软件渲染，沿用窗口缩放/最大化黑屏问题的既有规避。除非有本机重复测试证据，不要贸然切回 GPU 默认模式。
- 本地图表按需在随机 `127.0.0.1` 端口运行，复用对应任务会话，退出时清理所属进程树，不对外监听。
- 性能预算见 [QUALITY-GATES.md](QUALITY-GATES.md)：实验室启动每轮 ≤5s，工厂选择/阶段切换等 p95 ≤200ms；至少同机 3 轮，记录 CPU/内存、渲染异常、缩放和真实清洗中的界面响应。不能冒称网站真实 INP 或所有硬件保证。
