# 华虹 DCP 输入、原输出与 CP 本地图表恢复

日期：2026-10-26。客户端：0.2.2-m1。计算适配层：studio-engine-20261026.2。

## 问题与修复

用户反馈华虹 DCP/TXT 输入、输出与旧工具不同，而且没有本地图表。实际旧历史中三份 CSV 已存在：新版界面优先展示传输 ZIP，打开的是任务归档目录，并把直接文件及 ZIP 中的相同内容重复显示为六张表。原 CP Cockpit 入口和 Streamlit 依赖也未迁入新工作台。

- 直接进入清洗文件夹，支持另存原文件夹；ZIP 明确作为完整归档。
- 新任务按首个真实 Lot 与时间创建输出目录；旧历史保持原样，展示时核对内容哈希后去除重复预览。
- 华虹支持单/多文件、递归目录及 ZIP/7z/7zip/RAR；递归发现目录内压缩包，兼容包内多层目录。散文件须保留可确认的产品/批次上级目录。缺失身份、目录与头部冲突、重复 Lot+Wafer 均停止处理。
- 复用原清洗、单位、规格、Bin/良率逻辑，不修改原 CP/FT 仓库或原工具发行包。
- 历史及结果页恢复“查看CP图表”。图表使用已校验结果副本、原 CP Cockpit，在随机的 127.0.0.1 端口运行；同任务重复打开复用服务，客户端退出时关闭所属进程树。
- 单独锁定图表补充依赖，不覆盖既有计算库；对新版 Streamlit 的图像宽度参数做界面兼容转换。原界面反复写入未变化的筛选状态，在新控件中会导致选择回退；仅在临时图表副本中改为选择真正变化时写入，原包及统计算法不变。

## 数据对账

使用实际华虹 ZIP：25 个 TXT 晶圆文件，3,875 条清洗数据。以同一固定版 CP 工具、原 GUI 参数运行得到基线，与用户原成功任务的 cleaned/yield/spec **三份文件逐字节一致**。

| 输入场景 | 预期与实际 | 对账 |
| --- | --- | --- |
| 原始 ZIP | 成功 | 3,875 条，三份 CSV 与基线字节一致 |
| 递归原始文件目录 | 成功 | 同上 |
| 单个 TXT | 成功 | 155 条，测量单元格与对应原晶圆一致 |
| 多个 TXT | 成功 | 310 条，测量单元格与对应原晶圆一致 |
| 7z / 7zip / RAR | 三项均成功 | 全部三份 CSV 与基线字节一致 |
| 递归目录内 ZIP | 成功 | 同上 |
| ZIP 内多层目录 | 成功 | 同上 |
| 同时导入同批次 ZIP 与 7z 副本 | 预期失败且实际拦截 | 同一 Lot+Wafer 重复，不发布成功结果 |

10 个场景：9 个成功，1 个按预期拒绝。7z 和 RAR 是用原 TXT 内容制作的真实格式归档；RAR 为 stored RAR4，用于验证读取链路，不代表所有厂商 RAR 版本均已覆盖。未测试加密或分卷压缩包。

原输出结构：cleaned 3,876 行（含表头）×20 列；yield 27×7；spec 10×15。成功结果只显示三张原表。表格预览保留表头/规格行，清洗记录数独立显示 3,875。
