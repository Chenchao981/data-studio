# 功能、性能、稳定性验收

这三项是客户端的首要约束。外观必须在约束内优化；没有实测收益时，不增加框架、复杂缓存或后台工作。

## 工厂名称约定

JETECH 的中文名称固定为“佳泰”，拼音 `jiatai`，简称 JT。内部代码保持 JETECH；不能自行翻译成其他工厂名称。历史文件和执行回执保留原件，界面按代码显示正确名称。

## 功能与取舍

- 保持 CP/FT 原工具的输入合同、工厂操作、身份、单位、规格、Bin/PAT/良率及输出语义。界面优化不能减少校验或修改清洗计算。
- 保留任务取消、错误提示、本地历史、输出路径设置和可追溯日志。优先简化装饰动画、模糊/透明效果、大面积阴影、重复刷新、自动展开的大量内容。
- 不恢复启动演示、Excel 自动预览或自动读取完整结果表。图表按需打开，清洗在独立计算进程执行，界面不承担数据解析。
- 工厂区限定可视高度；20 家规模用简单卡片和本地筛选即可。日志增量读取，每次至多64 KiB，显示至多1000行/60000字符，保留磁盘完整日志。

## 本机观察预算

这些是本项目的实验室验收线，不代表每种硬件的承诺，也不等同网站真实用户 INP。

| 检查 | 本机目标 |
|---|---|
| 可见客户端启动到工作台控件就绪 | 连续启动每次不超过5秒；另外记录重启电脑后的首次启动 |
| 工厂选择、CP/FT 切换、搜索 | 每轮 p95 不超过200毫秒；记录最大值与样本数 |
| 真实清洗期间界面100ms定时器额外延迟 | p95 不超过200毫秒；单次明显停顿单独调查 |
| 稳定性 | 无前端异常、意外重载、渲染进程崩溃或采样黑屏 |
| 回归 | 同机同流程出现超过20%的重复退步，且绝对差超过20毫秒，需要定位；不因单次噪声直接回退 |

交互时间从脚本触发到 DOM 状态确认后的两次动画帧，包含渲染调度等待，是实验室代理指标。200ms 目标借鉴 [web.dev 响应性指导](https://web.dev/articles/optimize-inp)，不能将此结果标成真实 INP。监测渲染终止信号参考 [Qt QWebEnginePage](https://doc.qt.io/qt-6/qwebenginepage.html#renderProcessTerminated)。

## 测试方法

1. 在独立 `--home` 中测试，使用 CP/FT 工具已有的真实样本。模拟工厂只用于容量与布局测试，不写入生产工具目录，不据此声称支持新工厂。
2. 性能测试必须使用可见窗口，串行运行，记录软件/硬件渲染模式和显示缩放。同一版本至少3轮；新旧版使用相同工厂切换流程，搜索另测。热缓存连续启动与真正冷启动分开记录。
3. UI 改动运行类型检查、冻结客户端菜单/工作流检查、20家工厂检查，以及原生窗口缩放/最大化/跨屏检查。涉及任务、日志、路径、安全时运行相应测试。
4. 处理器或数据规则改变时另跑原 CP/FT 测试数据集并对账，不用 UI 测试替代数据验收。
5. 保留原始时间序列、前端异常、定时器延迟、截图与测试回执。JS 堆和渲染线程占用不能冒充整棵客户端进程树的内存/CPU；长时间运行的内存增长要另做耐久测试。

在仓库根目录执行（输出目录每次使用新名字）：

```powershell
node desktop-data-studio/apps/web/tests/measure-ui-performance.mjs <客户端exe> <独立证据目录> --strict
desktop-data-studio/.venv-cpython/Scripts/python.exe desktop-data-studio/tests/verify_factory_ui.py --output <20家工厂证据目录>
desktop-data-studio/.venv-cpython/Scripts/python.exe desktop-data-studio/tests/verify_resize.py --software --output <窗口证据目录>
node desktop-data-studio/apps/web/tests/verify-bundle-ui.mjs <客户端exe> <含真实完成任务的独立home> <工作流证据目录>
```

`--strict` 在超出启动/交互预算时返回失败；不带参数可用于采集旧版对照，超标回执为 REVIEW。测试不得关闭用户正在处理的任务。未发现性能退步时保留有用设计，不为“优化”引入新的复杂度。
