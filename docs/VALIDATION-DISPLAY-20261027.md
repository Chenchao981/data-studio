# 显示缩放与界面恢复验证 · 2026-10-27

版本：Desktop Data Studio 0.2.4-m1。本机程序已更新，范围为显示稳定性，不涉及服务器发布或账号同步。

## 现象与判断

用户反馈调整分辨率时卡顿、偶发黑屏。检查发现原客户端没有渲染进程退出或界面无响应后的恢复入口。当前电脑有两块显卡及虚拟显示驱动，但这些信息不足以确认黑屏根因。

本次连续缩放没有稳定复现原始偶发黑屏，因此改动定位为显示兼容性缓解、重绘优化和故障恢复，不能据此宣称已证明原始故障的唯一原因。

## 实施

- Windows 默认采用 Qt/Chromium 软件渲染，启动时仅设置当前进程的显示选项；不修改系统环境变量或驱动。采用 [Qt 官方软件渲染方式](https://doc.qt.io/qt-6.10/qtwebengine-features.html#hardware-acceleration)，不关闭 Chromium 安全隔离。
- 监听屏幕、可用区域、DPI 变化，合并到 160 ms 后调整窗口范围并重绘。正常缩放不重新载入页面，也不暂停界面绘制。
- 演示图表合并连续尺寸变化，100 ms 稳定后重画；隐藏/零尺寸时跳过绘制，卸载时取消待执行回调。
- 渲染进程异常后显示原生恢复页，自动重载一次；一分钟内再次异常则提供手动按钮，防止连续重载。按钮与自动恢复互斥。
- 界面心跳未返回、页面加载超时会出现可操作的恢复提示。恢复仅重载界面，任务管理器、清洗进程及历史工作区继续保留，不自动重提任务。
- 增加显示模式、屏幕变化、渲染异常和心跳超时日志，便于继续定位偶发问题。

## 验证

- 32 项自动测试通过；新增兼容设置作用范围、参数保留和恢复次数限制测试。前端类型检查与生产构建通过。
- 原生窗口分别在工作台、真实结果表和演示图表中进行 100 次尺寸变化、4 组最大化/还原及跨屏测试；抽检画面没有全黑/空白，正常缩放没有渲染进程异常。
- 实际窗口先后处于 150% 和 125% 两块屏幕，读取窗口所属屏幕及 `devicePixelRatioF`，确认是实际跨屏，而非仅修改网页视口。正常缩放前后的页面标记保持，证明没有靠重载页面掩盖问题。
- 真实结果表测试中最大 Qt 调整周期约 35 ms，页面心跳最大间隔约 79 ms；这些是本机单次压力测试观测，不代表所有机器或系统分辨率切换性能。
- 实际结束测试窗口自己的渲染进程：第一次自动恢复，后台演示任务继续完成，任务数量未增加；第二次触发重试限制，点击按钮后恢复。另通过过期时间注入验证无响应和加载超时提示分支。
- 已安装 EXE 在隔离 PATH 下启动，日志确认默认 `rendering=software`；真实历史、结果预览、选择器、深色主题和小窗口检查通过，无前端脚本异常。
- 程序与资源差异已有回退记录，旧文件已备份，更新后逐一校验 SHA-256。截图、日志、安装清单和回退文件保存在忽略目录 `artifacts/resize-20261027`。

## 验证边界

未更改用户 Windows 全局显示设置；测试覆盖程序窗口变化与已有不同缩放比例屏幕之间的实际移动。原始偶发黑屏仍需按用户触发条件继续复测，不能把抽检未出现黑屏等同于已彻底解决。

- 新打开普通客户端窗口，使用现有本地工作区；只进行窗口操作、打开既有结果和返回工作台，没有新增清洗任务或修改输入、输出配置。
- 工作台点击标题栏最大化、还原；右侧最外缘拖拽后，截图尺寸从 1503×991 变为 1201×991。

- 上述成功操作后界面、结果表均恢复显示，没有复现持续黑屏；本次启动后的日志没有渲染进程退出或心跳超时记录。最初未命中外缘的拖拽，以及因目标超出窗口被工具拒绝的放大尝试，不计入成功操作。

这组实际鼠标操作与前面的程序驱动压力测试分别记录；不是新增的 100 次鼠标拖拽验证。本轮仅补充验证证据，没有新增显示策略改动，也未验证清洗任务繁忙期间的持续鼠标拖拽。
