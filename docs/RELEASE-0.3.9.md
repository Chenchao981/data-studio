# Data Studio 0.3.9：工作台实时清洗日志与耗时优化

2026-10-30。应用0.3.9，计算组件`studio-engine-20261030.2`。继续使用固定CPython 3.13.17、原CP/native FT/shared FT包；PAT核心、清洗统计规则和CONT图表过滤不变。

## 用户可见行为

- 取消侧栏和工作台标题旁的“任务进度”。右侧上方显示当前文件/文件夹、所选功能和简洁“清洗”按钮；下方直接展示实时日志，启动后留在工作台。
- 原CP/FT读取/处理文件等真实日志实时追加，250ms增量读取，最多保留1000行/60000字符用于显示。向上滚动暂停跟随，点“回到最新”恢复；完整日志留在本机。无伪造百分比或模拟文件进度。
- 取消、错误、完成和查看结果都在同一区域；历史可重新打开日志。多项输入仍可在折叠区调整选择与合并方式，内部串行处理，运行期间禁用重复启动。
- 清洗结果“完成时间”改为“清洗耗时”，小于一分钟显示秒，否则分秒。从实际运行到保存结果结束计时，不含排队；旧历史用started/finished计算，缺少开始时间则显示“—”。原结束时间仍在历史详情保留。
- 输入/输出继续允许粘贴和修改路径；取消独立监控入口不删除用户历史。

## 速度原因与措施

瓶颈主要来自工作台外围流程，并非更换了统计内核：原流程每任务复制542个约8MB的Excel/压缩依赖文件，重复启动解释器，FT完成后又用openpyxl逐格读取整份Excel获得身份概要，并对已经压缩的结果重复压缩。

现在直接绑定指定固定组件中的依赖与计算包，仍逐文件核对SHA256及路径范围；清洗在已有的一次性隔离工作进程中调用原入口，省去再启动一层解释器，并显式禁用用户目录依赖与运行时字节码写入。PAT及其他操作保留原隔离子进程路径。FT身份概要采用流式XML读取文本Lot及行数；遇到数值/日期类Lot回退原读取器。XLSX/ZIP/PNG等不再重复压缩。原输入前后指纹、规格/身份规则、结果哈希、历史、输出复制校验及进程树退出控制保留。

立昂微真实回归发现原Excel读取器的循环引用可能延迟关闭临时文件；在释放临时输入前回收不可达对象，复测成功。未修改原始Excel、测量内容或原清洗规则。
