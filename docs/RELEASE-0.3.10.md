# Data Studio 0.3.10：预热计算进程与默认功能

2026-10-30。应用 0.3.10，计算组件 `studio-engine-20261030.3`，仍使用固定 CPython 3.13.17 和原有 CP/native FT/shared FT 包。没有升级清洗算法、PAT 算法或第三方依赖。

## 使用变化

- 启动后在后台预热 CP、原生 FT、日月光 shared FT 三个独立进程。成功清洗后复用对应进程，不在不同包之间混用模块。
- 顶部按当前功能显示“引擎预热中 / 本地引擎就绪”；取消或失败后的进程待重新建立时显示“引擎待启动”。用户可以提前开始，等待时间仍计入清洗耗时。
- 切换 CP/FT 工厂后默认选择最左侧可用清洗功能；首次打开工作台也有默认项。华虹顺序仍为华虹数据清洗、TD 数据清洗、PAT、图表。
- 主按钮统一为“开始清洗”。输入/输出粘贴修改、实时日志、历史、结果耗时继续保留。

## 执行与安全边界

清洗任务仍串行。工作台中的线程只负责通信和保存，计算留在固定解释器的独立进程中。各任务有独立工作目录、输入指纹、结果和回执；取消、异常或进程崩溃后销毁对应进程，下次重新预热。关闭客户端回收全部计算进程及其子进程，包括未复用的 PAT 分析进程。

每次仍校验任务引擎清单、包文件、实际依赖文件、输入前后哈希和结果哈希。预热缓存的是模块和经过验证的依赖描述，不缓存用户源数据或计算结果。日月光复用原来的共享包执行脚本，没有重写解析或计算口径。PAT、图表和其他分析继续独立执行。

华虹压缩包直接保留成员路径解压，避免先解压一次再因目录不适配解压第二次。校验真实批次/片号后移动自有临时解压文件，跨卷时自动复制；原始文件仍只读。重复 Lot/Wafer、身份不一致、路径越界等检查保留。

常驻进程会增加待机内存占用。FT 大工作簿的结果身份扫描仍有成本，本次没有省略它，也没有改成仅显示计算函数耗时。

## 同机三轮实测

旧版使用 0.3.9 原代码和其独立发布引擎；新版使用 0.3.10 发布目录里的引擎。两组串行运行，各样本三轮；新版表中时间为后台预热完成后的任务总耗时，包含校验、清洗、结果整理和发布。

| 真实样本 | 0.3.9 中位数 | 0.3.10 中位数 | 耗时减少 |
|---|---:|---:|---:|
| 华虹 100 文件，14,200 行 | 8.78 秒 | 2.93 秒 | 66.7% |
| 华虹 13 片，1,950 行 | 5.75 秒 | 1.04 秒 | 82.0% |
| 上海捷敏 DC，67,132 行 | 8.73 秒 | 6.73 秒 | 22.9% |
| 日月光 DC，3,900 行 | 5.74 秒 | 3.28 秒 | 42.9% |

新版三轮分别为：100 文件华虹 3.428/2.760/2.926 秒；13 片华虹 1.146/1.035/1.023 秒；上海捷敏 7.555/6.733/6.631 秒；日月光 3.675/3.193/3.277 秒。

本次三个进程全部预热用时 5.65 秒，发生在后台。另测新会话立即提交 100 文件华虹任务，含预热等待共 8.43 秒；这不是重启操作系统后的冷启动测试。不能把预热后的 2.93 秒当作刚启动即点击的耗时，也不能据此宣称所有样本已达到原工具纯计算速度。

## 验证

- 12 个新版任务与对应旧版逐项对账：CP CSV 所有单元格、FT Excel 全部 `xl/` 业务部件相同；日月光结果 ZIP 内的 Excel、解压后的散点 CSV、规格 CSV 和业务清单一致（只排除清单创建时间）。批次/片号概要一致，源文件内容和输出哈希通过。
- CP 两种样本交替执行仍复用一个进程，两个 FT 包分别复用自己的进程，三个 PID 互不相同。
- 真实取消、崩溃恢复、错误压缩包后重试、退出停止清洗与 PAT 子进程通过，无未完成结果发布。
- CP/FT 的指定 kit 检查核对操作系统返回的实际 runtime 路径、启动参数、搜索路径、包哈希及任务注册表，不仅检查父进程配置。
- 佳泰清洗、立昂微清洗、华虹原始 PAT、上海捷敏原始 PAT 回归通过。固定 native/shared PAT 模块哈希一致。
- 完整回归 102 通过、1 因 Windows 符号链接权限跳过；类型检查与前端构建通过。
- 实际 Qt 验证 10 家工厂的默认功能、全部 37 项可见功能、明暗主题与 920/1440 宽度；真实冻结 EXE 验证输入/输出编辑、滚动日志、清洗耗时和保存位置。
